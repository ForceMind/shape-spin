# Shape Spin · 形状转转：游戏规格

> 本文是当前实现的冻结目标与迁移约束。原始需求全文由用户在会话中提供；本文件保留工程需要遵循的可验证约束，不替代原需求。

## 产品与边界

- 单机、离线优先的 H5 益智游戏；默认英文，完整支持简体中文。
- 交付主线 200 关（10 章 × 20 关）、每日挑战、自由练习及隔离开发编辑器。
- 不实现账号、联网排行榜、对战、支付、广告、现金或虚假在线功能。
- 发布静态 `dist/` 和同源码构建的 `release/shape-spin.html`。

## 冻结规则

1. 棋盘仅由有效格组成；缺失格是墙。零件具有稳定 `id`、`shapeId`、`colorId`、`typeId`，匹配必须同时满足形状和颜色。
2. 未声明 `exits` 时，顶行有效格为出口。零件移除后作为空格起点；只有经四向空格连通到出口时可取出。路径不能穿越零件、墙、缺失格或斜角。
3. 三列转轮共享一个当前目标排索引；每排 1—3 个有效孔槽，按从左到右填入。目标排、顺序与预览均为固定关卡数据。
4. 暂存容量固定为 5。合法取出优先直接归位，否则进入最左空位。任意暂存零件可自动归位；同类型使用最早进入的零件；空位稳定左移。
5. 满格时，直接匹配当前目标的可取出零件仍然合法；不能匹配的取出非法，绝不允许第六格。
6. 每次合法取出和 SPIN 都执行确定性自动结算：匹配暂存 → 完成当前排 → 循环切换下一未完成排 → 重复，直至稳定或胜利。
7. SPIN 仅在尚有次数且存在其他未完成排时有效；消耗一次并按固定循环切换。不会随机改题、复位填充或消耗空转。
8. 胜利需源棋盘为空、暂存为空、所有有效孔槽填满。稳定后无合法取出且无合法 SPIN 时失败。
9. 撤销以玩家动作而非动画事件为单位，恢复动作前完整局面。提示、撤销、实际 SPIN 使用等 `RunAudit` 不可随撤销回退。
10. 每次规则动作是原子事务：验证 → 演算与结算 → 不变量校验 → 提交；失败绝不残留部分变更。

## 强制不变量

- 每个零件恰在棋盘、暂存、已填目标之一；没有重复或丢失。
- 关卡初始供给与全部目标需求按 `typeId` 完全守恒。
- 填入零件与目标类型匹配；暂存不超过 5；SPIN、活动排和完成状态合法。
- 游戏内核不依赖 DOM、Canvas、音效、帧率、浏览器时间或 UI 文案。

## 稳定模型与 API

- `LevelDefinition`、`GameState`、`PlayerAction`、`GameEvent`、`RunAudit`、`SaveEnvelope`。
- `createGame`、`getSelectablePieces`、`getLegalActions`、`applyAction`、`settle`、`validateLevel`、`validateState`、`serialize`、`deserialize`、`replay`。
- 求解器必须调用正式内核，结果严格标记为 `solvable`、`unsolvable` 或 `unknown`；`unknown` 绝不可标成无解。

## 兼容与迁移

- 保留旧八关的稳定映射与类型语义；不得通过换色凑关。
- 检测旧键 `shape-spin-demo-v1`，备份并尽可能迁移通关、关卡、声音与可验证局面；不可转换局面可要求重开但不丢全局进度。
- 奖励按稳定关卡身份或每日身份幂等记账，不依赖 `runId`，不随撤销或重玩重复发放。

## 质量要求

- 规则、内容、浏览器测试必须分开记录真实结果。
- 全部 200 关须通过结构与供需校验，并以正式内核重放 witness 至真实胜利。
- 生成验证至少统计 1,000 个固定 seed，记录成功、去重、预算耗尽及回退。
- 浏览器回归使用真实 HTTP 生产构建，覆盖代表关、存档、动画取消、移动视口、每日、练习、编辑器和双产物。
